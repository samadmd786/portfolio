NucleusCloud

Fully event-driven bioinformatics data pipeline on AWS - Flask frontend, presigned S3 uploads, SQS/SNS workers, Lambda triggers, Step Functions archival workflow, Stripe billing, and Globus Auth. Entire stack provisioned from a single CloudFormation template.

How it works

1
Authentication via Globus Auth

Researchers authenticate through Globus Auth — a federated identity system trusted by institutions like NIH, XSEDE, and national labs. On successful login, Flask issues a scoped session token and provisions the user's storage quota via Stripe subscription tier.

2
Presigned S3 Upload

The Flask backend generates a presigned S3 URL server-side — the file bytes go directly from the user's browser to S3 without passing through the application server. This eliminates bandwidth bottlenecks and reduces server load to near-zero for large genomics files.

3
SQS + SNS Event Fan-out

S3 upload completion triggers an SQS message. SNS fans this event out to multiple subscribers — the processing Lambda, the notification service, and the billing metering endpoint — all decoupled and independently scalable. No polling, fully push-driven.

4
Step Functions Archival Workflow

SNS triggers a Step Functions state machine with three stages: (1) Validate — checksum verification and format validation, (2) Process — indexing and metadata extraction, (3) Archive — tiered storage migration to S3 Glacier for cost-optimized long-term retention. Each stage is independently retryable with configurable backoff.

5
Glacier Hydration on Demand

A dedicated Lambda handles Glacier restore requests. When a researcher requests a previously archived file, the Lambda initiates an expedited or standard Glacier retrieval job, monitors completion via CloudWatch Events, and returns a presigned download URL when the file is available.

6
One-Command Infrastructure

The entire stack — IAM roles, S3 buckets, SQS queues, SNS topics, Lambda functions, Step Functions, VPC networking — is defined in a single CloudFormation template. LocalStack mirrors the AWS environment locally for development. Moto mocks AWS service calls in unit tests, achieving full test coverage without cloud costs.
